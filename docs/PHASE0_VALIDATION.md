## Resumption: security and CI gates

The interrupted run left PR #1 with a failing secret scan. Three detections were
independently reproduced synthetic event hashes, not credentials. The remediation
and positive/negative controls are documented in `SECRET_SCAN_REVIEW.md`; the full
history scanner and all five actual scanner controls passed on GitHub at `31cc611`.

Inspecting that run's archived check output then revealed a separate problem: the
implicit Actions shell allowed `tee` to hide a formatting failure. Its green test-job
status was NOT evidence that the later type/test/proof gates ran. Do not use that
intermediate green status as final verification. The workflow now explicitly selects
Bash with pipefail, captures stderr with stdout, and has regression tests for failure
propagation. The check runner prints `FOUNDATION_CHECK_COMPLETE` only after every gate,
including the integrated proof, completes. Final CI must contain that marker and the
actual pytest count, not merely a green status badge.

After these corrections, **297 tests passed locally** on the extracted CI source plus
the resumption patch. The queued transcript/localization/FFmpeg proof, immediate
invalidation, restore, boundary and environment checks also passed locally. The final
PR run remains authoritative for complete locked-tool and container verification.
The archive generated by CI contains tracked source only and the tested merge SHA.
